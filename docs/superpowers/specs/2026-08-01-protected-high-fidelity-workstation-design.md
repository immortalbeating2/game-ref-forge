# Round 15 受保护的高保真工作台重建设计

日期：2026-08-01  
状态：设计方向已确认，书面规格待复核  
视觉基准：`docs/product/assets/round-14-visual-target.png`  
稳定生产基线：Sites version 18 / `4ec8659`

## 背景

Round 14 已完成高密度参考卡、工具栏、对比坞、结构化详情、密度偏好和石墨纹理，并通过完整功能、响应式与生产验证。然而同视口比较显示，实现主要完成了文字、信息顺序和交互合同，未充分还原目标图的美术表现：中心画布占比不足，纹理被不透明表面遮蔽，无安全预览时退化为大面积纯色分类块，左右侧栏与工具栏仍呈现明显的通用后台盒子感。

Round 15 不重新定义产品，而是执行一次“受保护的 A”视觉重建：尽量还原目标图的构图、材质、图像墙密度和研究工作台气质，同时冻结已经验证的业务、数据与核心交互合同。

## 决策摘要

采用“受保护的高保真 A”，不采用字面照抄目标图的方案。

- 高保真重做：页面构图、表面层级、背景、卡片、工具栏、筛选外观、详情外观、对比坞外观。
- 完全保留：私有研究定位、来源与授权边界、reference/synthesis 数据、API、D1、migration、Backup v1、CRUD、搜索排序、单选筛选、2-4 条有序对比、综合稿交接、分栏拖拽/折叠/键盘、双语和响应式能力。
- 有限新增：原创分类纹理回退、小型只读评分雷达图、更加明确的对比选择反馈。
- 明确不新增：通用批量选择、Shift/Ctrl 选卡、参考卡拖拽排序、筛选多选、公共展示、第三方媒体托管和新的业务字段。

## 目标

1. 让目标图的构图和视觉气质成为真正可验收的界面约束，而不只是概念参考。
2. 在默认只有两条 seed reference、且二者没有 `preview_url` 时，界面仍像完成的美术参考工作台。
3. 将中心参考画布恢复为主角，在大桌面默认状态下占可用工作区至少 60%。
4. 让石墨纹理、青绿色信号色、图像墙和扁平检查器构成一个连续视觉系统。
5. 让“开始对比”后的选卡方式无需猜测：普通点击即可选择 2-4 条，并持续显示数量、顺序和下一步。
6. 保持已验证的数据安全、键盘可达、移动触控、无横向溢出和设备偏好能力。

## 非目标

- 不修改 API route、D1 schema、migration、reference/synthesis 领域模型。
- 不修改 Backup v1 schema 或其 `workspace_layout.version: 1` 合同。
- 不重新设计添加、编辑、删除、导入、导出或恢复的业务流程。
- 不把参考筛选改成多选模型。
- 不引入 masonry、无限滚动、虚拟列表或新的依赖。
- 不下载、缓存或重新托管第三方预览媒体。
- 不根据第三方作品生成近似图；原创分类纹理只表达抽象的材质和类别气质。
- 不借本轮进行无关的页面架构、数据层或状态管理重构。

## 产品合同冻结

### 数据与安全

- 所有 reference、synthesis、relation、snapshot 字段和校验保持不变。
- 原始 `preview_url` 只有在当前安全策略允许时才显示；加载失败后回退到本地原创分类纹理。
- 未知授权不因视觉重建而获得新的公开或媒体展示权限。
- seed reference 继续是只读示例，不伪装为已托管第三方媒体。
- 原创纹理是应用资产，不包含可识别的第三方角色、标志、构图或作品片段。

### 现有工作流

- 保留搜索、排序、密度切换、置顶、添加、编辑、删除、Markdown 导出和数据管理。
- 保留左侧各维度的单选筛选语义；视觉上可呈现为紧凑选项或选择器，但不出现会暗示多选的复选框。
- 保留 reference 单选详情与 comparison 多选模式的区别。
- 保留 2-4 条有序比较和综合稿交接；顺序继续由加入比较的先后决定。
- 保留分栏拖拽、键盘调整、双击复位、折叠和恢复。
- 保留紧凑/舒适两档网格密度，不引入横向列表模式。

## 信息架构与构图

### 大桌面默认比例

工作区仍由左研究栏、中参考画布、右检查器组成，但中心优先。

- 左栏默认宽度目标：`224px`。
- 右栏默认宽度目标：`360px`。
- 左栏建议范围：`208-320px`。
- 右栏建议范围：`336-520px`。
- 中心最小宽度需要结合断点调整；在 1480-1600px 验收视口，中心画布占工作区至少 60%。
- 分隔条和折叠恢复轨道继续计入布局解算，约束态仍优先保护中心可用宽度。

这些数值是设计目标，实施计划需要用布局纯函数测试锁定最终常量。

### 左侧研究栏

- 品牌、语言、工作区切换和研究控制保持原顺序。
- 用一条连续、低对比度的工作台表面取代多个独立卡片容器。
- 标签字号、间距和分组线形成节奏；控件不再占用不必要的垂直空间。
- 每个筛选仍是单值。若采用列表式视觉，必须使用 `radio`/单选按钮语义或明确的单选下拉，不使用 checkbox。
- “清除筛选”保持可见，并仅在存在筛选时获得更高强调。

### 中央参考画布

- 顶部由搜索、排序、密度、数据管理、对比和新增组成一条命令轨道。
- 标题、结果数量和主要动作属于同一视觉层级，不再被多个边框盒子切碎。
- 紧凑模式以四列图像墙为大桌面目标；舒适模式以三列为主要目标。
- 网格根据实际中心宽度自适应，不能为了固定列数造成小于可读宽度或横向溢出。
- 参考卡之间使用稳定窄间距，让预览图成为整体图像墙；画布边缘保留足够呼吸区。

### 右侧检查器

- 右栏是连续检查器，不是卡片套卡片。
- 顶部保留标题、来源、安全摘要和关键动作。
- 评分矩阵与雷达图并列或上下组合；雷达图只辅助扫读，数字仍是权威值。
- 质量清单、标签轴、灵感条目和编辑入口继续按渐进披露组织。
- 分区使用细分隔线、标题、留白和轻微表面差，而非每段独立厚边框。

### 对比坞

- 进入比较模式后，中央画布和底部坞共同显示 `0/4` 到 `4/4` 状态。
- 每张卡出现清晰的选择控制、序号与选中描边；普通点击即可加入或移除。
- 底部坞以紧凑缩略条展示顺序，保留移除、取消和交接到综合稿。
- 不要求 Ctrl/Shift，不新增自由拖拽排序；顺序继续由选择先后决定。
- 少于 2 条时明确解释为何不能交接，避免仅以 disabled 按钮表达。

## 视觉系统

### 石墨基底

- `workbench-graphite.webp` 或其经过验证的替代资产必须在中心工作区肉眼可感知。
- 页面背景由低频石墨纹理、轻微暗角和局部冷色光晕组成，不采用均匀纯黑。
- 左右栏可以更实，但不得使用高不透明度表面层层覆盖至完全看不到材质。
- 文本承载区域必须有足够对比，纹理不得穿透到影响小字号阅读。

### 表面层级

限制为四级：页面基底、侧栏/检查器、命令轨道与卡片、浮层/模态。

- 减少大圆角容器套小圆角容器。
- 主表面优先使用边缘、明度差和留白区分层级。
- 圆角保持克制：工作台表面小圆角，预览与交互控件中等圆角，模态可略大。
- 阴影只用于浮层、被抬起的交互态和必要的画布分离，不为每个盒子添加阴影。

### 色彩与状态

- 青绿色继续作为主要信号色，用于主动作、当前模式、选择序号和高价值状态。
- 状态色保持语义：安全/完整为绿，提醒为琥珀，危险/删除为红。
- 大面积青绿底只用于原创分类纹理中的局部光层，不让整张卡成为纯色块。
- focus、hover、selected、comparison-selected 和 pinned 必须可区分，且不只依赖颜色。

### 字体与图标

- 继续使用项目现有字体栈和 lucide 图标，不增加字体或图标依赖。
- 标题采用更紧凑的字重与行高，正文维持可读尺寸。
- 图标按钮保留可访问名称和 tooltip；主要动作继续显示文字。

## 原创分类纹理

### 资产策略

为 `ASSET_CATEGORIES` 中实际使用的类别提供本地原创低干扰纹理。纹理不是示例作品，而是抽象研究底图，例如：

- UI/HUD：网格、对齐线、模块框和微弱扫描光。
- 材质：颗粒、表面起伏、样本切片和柔和高光。
- 角色/生物：轮廓节奏、关节点和动态线，不形成具体角色。
- 环境/场景：透视线、地形层次和雾化深度。
- 道具/武器：零件分区、结构轴线和材料切换，不形成具体武器设计。
- 特效/动画：轨迹、粒子流和时间切片。
- 音频/其他非视觉类别：波形、频段或中性抽象纹理。

实施时以仓库枚举为准建立完整映射，并提供一个通用 fallback。

### 显示优先级

1. 安全且成功加载的真实 `preview_url`。
2. 对应资产类别的本地原创纹理。
3. 通用石墨研究纹理。

加载失败必须切换到第二级，不能留下浏览器破图图标。纹理需要在暗色卡片上保持标题和状态文字可读。

### 性能约束

- 优先使用经过压缩的 WebP/AVIF 或可审计的轻量 CSS/SVG 资产。
- 单张分类纹理建议不超过 120KB；全部新增纹理的传输体积在实施计划中设预算并验证。
- 纹理应复用，不为每条 reference 生成独立图片。
- 不因纹理增加布局偏移；预览区域保持固定比例。

## 参考卡设计

### 结构

1. 固定比例预览区。
2. 顶部类别和置顶控制。
3. 标题、站点/作者。
4. 授权、公开状态、质量状态等主要徽标。
5. 紧凑评分摘要。
6. 根据密度决定是否显示次要标签。

预览区优先，文本区不再占据卡片大多数面积。相邻卡片的预览上下边界必须对齐。

### 密度

- 紧凑：四列目标、隐藏次要标签、保留足以判断来源和安全性的核心信息。
- 舒适：三列目标、显示次要标签和更完整评分摘要。
- `<=820px` 使用舒适触控回退，隐藏密度切换，交互目标至少 `44x44px`。
- 两档仍是同一种卡片结构，不产生“列表模式”的错误暗示。

### 状态

- 普通选中表示右侧详情对象。
- 比较选中显示序号、选择控件和显著描边。
- 置顶显示独立图标状态。
- 三者可以同时存在，但必须通过位置和形状区分。

## 评分雷达图

雷达图完全由现有五个评分派生，不新增字段：

- 综合评分：`rating`
- 参考价值：`reference_value_score`
- 可转化性：`transformability_score`
- 制作就绪度：`production_readiness_score`
- 安全度：`6 - copyright_risk_score`

所有轴均映射到 1-5，数值缺失时使用明确的“未评分”降级，不绘制误导性的零值。

- 雷达图需要可访问名称和文本摘要。
- 数字矩阵始终保留，雷达图不承担精确读数。
- 图形使用轻量 SVG 或 CSS，不增加图表依赖。
- 中英文轴标签需要在窄右栏中不溢出。

## 布局偏好兼容

`workspace_layout.version` 继续为 `1`，Backup v1 合同不变。不能仅为视觉代际调整把序列化版本改为 2。

为让已有设备获得新的中心优先默认值，采用独立的视觉代际标记或新的 localStorage 布局键：

- 首次进入 Round 15 时，旧默认附近的 `260/420` 布局重置到新默认。
- 用户明显主动调整过的宽度可以选择保留并按新边界 clamp；最终判定规则必须是纯函数并有测试。
- 从 Backup v1 恢复的 `workspace_layout.version: 1` 仍可解析，随后按新布局边界解算。
- 折叠状态尽量保留，不因视觉重置强制展开用户主动折叠的面板。
- 双击复位使用新默认值。

具体迁移策略在实现计划中先以测试固定，再接入 hook。

## 可量化视觉验收

### 必须满足

- 1480-1600px 默认三栏状态下，中心参考画布占工作区至少 60%。
- 紧凑模式在大桌面稳定形成四列目标，舒适模式形成三列目标；窄屏可按最小卡宽自然降列。
- 两条 seed reference 即使无 `preview_url`，也显示对应原创分类纹理，不出现大面积纯色占位或破图。
- 石墨纹理在截图中可辨识，但正文承载面不受干扰。
- 中央工具区表现为一条命令轨道，右侧表现为连续检查器，明显减少嵌套盒子感。
- 数字评分和雷达图同时存在，安全轴方向不误导。
- 对比模式可在无需修饰键的情况下选入 2-4 条，并持续显示顺序与数量。
- 1600/1280/1024/390px 的 document/body 横向溢出均为 0。
- 移动主要触控目标至少 `44x44px`。
- 所有既有自动化和业务流程回归通过，console error 0，QA 数据残留 0。

### 视觉评审判定

Impeccable detector 只作为反模式扫描，不再作为高保真的充分证据。最终批准必须同时包含：

1. 同视口目标/实现并排图。
2. 对上述量化指标的测量。

## 风险与控制

### 过度照抄概念交互

风险：把目标图中的复选框、Shift/Ctrl 或拖拽暗示误实现为新业务能力。  
控制：产品合同冻结；相关组件测试明确单选筛选和显式比较模式。

### 纹理影响可读性或性能

风险：背景太强、分类纹理太花或新增资产过大。  
控制：低频低对比纹理、文本承载面遮罩、资产体积预算、真实构建与浏览器检查。

### 布局迁移破坏 Backup v1

风险：误将布局序列化版本升级，导致旧备份无法恢复。  
控制：保持 `workspace_layout.version: 1`，迁移逻辑与 Backup 往返测试分离。

### 默认两条数据掩盖网格问题

风险：生产 seed 状态看似正常，但真实资料库密度下失真。  
控制：同时验证两条 seed 和至少 12 条多类别临时 fixture。

### 只重做参考首页

风险：添加/编辑、数据管理或综合稿仍停留在旧视觉系统。  
控制：同一 token 与表面规则覆盖所有既有工作流，浏览器验收逐项进入。

## 交付边界

Round 15 完成意味着：受保护 A 的视觉重建已实现、自动化与多视口视觉验收通过、文档留痕完整、独立复审批准，并在用户授权部署后完成生产验证。仅完成 CSS、仅通过 detector、或仅让默认截图变好看均不算交付。
