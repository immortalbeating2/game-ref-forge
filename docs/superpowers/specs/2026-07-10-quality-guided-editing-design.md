# Round 10 质量引导编辑设计

日期：2026-07-10

状态：已完成交互设计确认，等待书面规格审阅

## 背景

Round 9 已把现有 reference 字段派生为质量缺口、正向信号和整理队列，但详情面板中的质量清单仍是只读列表。用户发现缺口后，需要先记住字段，再手动进入较长的编辑表单寻找对应控件，来源、安全、灵感和评分之间的跨区跳转成本较高。

Round 10 聚焦这一段人工整理路径：让质量清单成为现有编辑表单的导航入口，同时保留统一手动保存和当前 API / D1 行为。

## 目标

- 让每个质量缺口都能直接进入现有编辑表单并定位到对应字段。
- 在一次编辑会话中提供上一项 / 下一项导航，支持连续补全多个缺口。
- 保持普通编辑入口、保存验证、取消语义和 D1 CRUD 行为不变。
- 支持中文优先与英文切换，并满足键盘、焦点和减少动态效果的可访问性要求。
- 通过单元测试、本地浏览器测试和生产临时 reference CRUD 验证真实可用性。

## 非目标

- 不增加自动保存、字段失焦保存或后台保存。
- 不增加批量编辑、批量标记或多条 reference 的连续处理队列。
- 不持久化补全导航进度或派生质量完成度。
- 不新增 API route、D1 column、migration 或 R2 binding。
- 不重做主工作台布局，不引入多步向导或新的编辑路由。

## 已批准方案

采用“编辑表单锚点导航”。质量清单继续展示派生缺口，但缺口条目由静态文本改为按钮。点击条目后进入当前详情面板的编辑态，滚动并聚焦对应控件，并在编辑表单顶部显示本次缺口快照的紧凑导航。

未采用以下方案：

- 清单内直接编辑：会复制现有表单控件和验证逻辑。
- 独立分步向导：会形成第二套编辑体验并扩大本轮范围。

## 交互流程

1. 用户选择一条 reference，在详情面板查看质量清单。
2. 用户点击一个待补全项。
3. 应用保存该 reference 当前的质量缺口快照和目标索引。
4. 应用复用现有 `recordToReferenceDraft` 创建编辑草稿并进入编辑态。
5. 编辑表单挂载后，目标控件滚动到可视区域、获得焦点并短暂高亮。
6. 编辑表单顶部显示补全导航，包括当前缺口文案、`第 X / Y 项`、上一项和下一项。
7. 用户可在同一草稿中补全多个字段，最后统一点击现有“保存修改”。
8. 保存成功或取消后清除导航状态；详情质量清单基于已保存记录重新计算。

普通“编辑”入口保持原行为，并明确清除补全导航状态。只有从质量清单进入编辑时才显示补全导航。

## 状态与数据流

Round 10 只增加组件内瞬时状态：

- `qualityEditIssues`：进入引导编辑时的质量缺口快照。
- `activeQualityIssueIndex`：当前导航索引。

状态转换：

- `startEditing(reference)`：建立普通编辑草稿，清除质量导航。
- `startQualityEditing(reference, issue)`：计算并保存缺口快照，定位目标 issue，建立编辑草稿。
- `moveQualityIssue(direction)`：在快照内切换索引，不循环；首尾禁用对应按钮。
- 保存、取消、切换 reference、筛选隐藏当前 reference：清除草稿和质量导航。

缺口快照在编辑期间不动态减少。这样不会把尚未保存的草稿误报为已完成，也避免为导航复制一套质量计算。保存后使用服务端返回记录重新计算。

## 焦点与视觉反馈

- 目标控件使用稳定 DOM `id`，不使用 URL hash。
- 编辑表单挂载后通过 effect 查找控件，调用 `scrollIntoView` 和 `focus`。
- 当前目标字段的 label 容器显示强调边框和轻量背景，不能仅依赖颜色。
- 强调动画短暂结束后，标准 `:focus-visible` 仍保留清晰焦点。
- `prefers-reduced-motion: reduce` 下使用即时滚动并关闭过渡动画。
- 390px 移动端将导航控件纵向收纳，且不能遮挡底部保存操作区。

## 异常处理

- 如果映射存在但 DOM 控件未找到，保持编辑态和草稿，显示本地化提示，不抛异常。
- 保存进行中时禁用上一项、下一项和取消之外的冲突导航动作。
- 如果 reference 因筛选变化被隐藏，沿用现有规则关闭编辑草稿并清除导航。
- 如果用户切换 reference，沿用现有“选择已切换”提示并清除导航。
- API 保存失败时保留草稿和当前导航位置，允许用户修正或重试。

## 无障碍要求

- 质量缺口使用 `<button type="button">`，支持键盘激活。
- 补全导航使用有名称的区域，并显示当前缺口与 `X / Y` 序号。
- 上一项和下一项在边界使用真实 `disabled`。
- 图标或箭头按钮提供中文 / 英文 `aria-label` 和 tooltip。
- 定位失败消息通过现有状态消息区域反馈。

## 验收标准

- 所有派生质量缺口都有可到达的编辑目标。
- 点击缺口后，目标控件成为 `document.activeElement`，并处于可视区域。
- 补全导航可在缺口快照中可靠前后移动，首尾不循环。
- 一次编辑可修改多个字段，并只通过现有保存按钮提交一次。
- 保存后质量清单使用已保存记录重新计算；取消不改变记录。
- 普通编辑、筛选、切换 reference 和保存失败行为没有回归。
- 中英文、键盘操作、减少动态效果和移动布局满足设计要求。
- 不产生 D1 migration、API route 或生产数据结构变化。

## 风险与控制

- `app/page.tsx` 已较大：本轮只增加聚焦状态和渲染，不做无关拆分；纯导航计算放入独立 helper。
- DOM ID 与质量字段可能漂移：使用强类型字段联合和完整映射测试锁定契约。
- 平滑滚动在不同浏览器表现有差异：验收以目标可见且实际获得焦点为准，不以动画轨迹为准。
- 生产浏览器控制曾出现超时：部署前先完成本地完整测试，生产测试使用临时数据并优先保证清理可验证。
