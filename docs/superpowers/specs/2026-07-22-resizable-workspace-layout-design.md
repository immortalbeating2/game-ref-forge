# Round 12 可调整工作台布局设计

日期：2026-07-22

状态：已完成交互设计确认，等待书面规格审阅

## 背景

RefForge 自 Sites 基础版起采用左侧筛选、中间参考卡组、右侧详情的桌面三栏工作台，Round 7 将其正式固化为当前比例。Round 11 增加综合稿后，这套信息架构仍然有效，但超宽桌面暴露出三个明显问题：左右面板固定且不可调整；左右面板和页面形成多重竖向滚动条；贯穿全高的硬边界让一个工作台看起来像三个割裂的小窗口。

Round 12 不重做产品信息架构，而是把固定 CSS Grid 升级为可调整、可折叠、可恢复且能记住用户偏好的桌面工作台。改造只影响前端布局和交互，不改变 reference、synthesis、API、D1 或来源策略。

## 目标

- 保留“左侧控制 / 中间工作区 / 右侧详情”的桌面信息架构。
- 在参考视图提供左右两条可拖拽分隔条，并给中间工作区保留安全最小宽度。
- 在综合稿视图保留左侧分隔条，右侧详情分隔条只在参考视图出现。
- 支持键盘调整、双击复位、左右面板折叠与恢复。
- 在当前浏览器中持久化用户的宽度和折叠偏好。
- 消除桌面外层多余滚动条，弱化三块独立窗口的视觉割裂感。
- 保持 1280px、1024px 和 390px 的现有响应式可用性与无横向溢出要求。

## 非目标

- 不增加可拖拽卡片、面板重排、浮动窗口或多显示器布局。
- 不在平板和移动布局启用拖拽分隔条。
- 不将布局偏好写入 D1，也不增加账户级云同步。
- 不修改 reference 或 synthesis 的字段、数据模型、API 和 CRUD 行为。
- 不重做筛选、卡片、详情或综合稿的内容结构。
- 不为 Round 12 引入通用仪表盘布局框架。

## 方案比较与决定

### 方案 A：只增加预设宽度

提供“紧凑 / 默认 / 宽详情”三个按钮。实现最轻，但无法解决不同显示器、不同研究任务下的连续宽度需求，也没有回应用户对拖拽的明确预期。

### 方案 B：原生 React 状态 + CSS 变量

使用聚焦的布局状态 helper、Pointer Events、键盘事件和 CSS Grid 变量实现。它不增加布局依赖，能够精确适配当前单页结构，并可通过纯函数和浏览器行为分别验证。

### 方案 C：引入通用 resizable panels 依赖

成熟库能提供完整的 panel group 抽象，但会要求重新包裹当前参考与综合稿 DOM、增加依赖，并把本项目只需要的两个分隔条扩张成更大的抽象。

Round 12 采用方案 B。当前需求边界明确，原生实现的状态规模小；但实现必须满足本规格中的键盘、边界、持久化和降级要求，不能只处理鼠标拖动。

## 桌面布局契约

### 参考视图

桌面宽度大于 1280px 时使用五轨网格：

```text
左侧面板 | 左分隔条 | 中间参考工作区 | 右分隔条 | 右侧详情
```

- 左侧默认宽度：`260px`。
- 左侧允许范围：`220-360px`。
- 右侧默认宽度：`420px`。
- 右侧允许范围：`340-640px`。
- 分隔条视觉命中区：`8px`，不额外挤压面板内容。
- 中间参考工作区的布局安全宽度：`560px`。
- 拖动任一分隔条时，宽度必须同时受面板自身范围和中间安全宽度约束。
- 浏览器缩放或窗口改变导致空间不足时，先收窄到允许下限；达到响应式断点后切换为既有非拖拽布局。

### 综合稿视图

- 沿用同一左侧宽度和折叠状态。
- 左侧分隔条仍可拖动。
- 综合稿工作区占据余下宽度，不渲染右侧分隔条或空白详情轨道。
- 从参考切换到综合稿再返回时，参考视图右侧宽度保持不变。

### 平板与移动

- `<=1280px`：不渲染可交互分隔条，不应用桌面自定义轨道；沿用左侧加主区、详情下置的响应式结构。
- `<=820px`：沿用单栏文档流，左右面板不固定高度。
- `390px`：所有布局控制不占据窄屏空间，页面级横向溢出必须为 0。
- 在窄屏修改方向或尺寸不能清除已保存的桌面偏好。

## 交互契约

### 指针拖拽

- 分隔条使用 Pointer Events，并在拖动开始后捕获指针。
- 拖动期间根元素显示对应列调整光标，并禁用意外文本选择。
- `pointerup`、`pointercancel`、组件卸载和窗口失焦都必须结束拖动状态。
- 每次移动通过同一个纯 clamp helper 计算有效宽度，不能在组件中复制边界算法。

### 键盘与语义

- 分隔条使用 `role="separator"`、`aria-orientation="vertical"` 和可聚焦的 `tabIndex`。
- 暴露当前值、最小值和最大值。
- `ArrowLeft` / `ArrowRight` 每次调整 `16px`；按住 Shift 时每次调整 `40px`。
- `Home` 移到有效最小值，`End` 移到有效最大值。
- 双击分隔条恢复该侧默认宽度。
- 中文和英文均提供“调整筛选面板宽度”“调整详情面板宽度”等可理解标签。

### 折叠与恢复

- 左侧品牌区提供折叠左栏的图标按钮；右侧详情标题区提供折叠右栏的图标按钮。
- 折叠后不销毁筛选、选中 reference、编辑草稿或综合稿状态。
- 折叠侧保留一个稳定的边缘恢复按钮，不能要求用户命中不可见的 1px 边界。
- 恢复使用折叠前宽度；若该宽度在当前视口不可用，则使用 clamp 后的宽度。
- 收起、展开和复位操作必须有本地化 `aria-label` 和 tooltip。

## 状态与持久化

新建 `WorkspaceLayoutPreferences`，只保存：

- schema 版本 `1`。
- `leftWidth`。
- `rightWidth`。
- `leftCollapsed`。
- `rightCollapsed`。

使用独立 localStorage key `ref-forge-workspace-layout-v1`。读取规则：

- 缺失值使用默认布局。
- 非法 JSON、错误 schema、非有限数字或非法布尔值全部安全回退，不阻塞页面渲染。
- 读取后的宽度先按静态范围归一化，再按当前容器可用空间计算有效值。
- 写入失败不影响当次布局使用；Round 12 不弹出阻塞性错误，只保留默认或当前内存状态。
- 现有 pinned references localStorage 契约保持不变。

## 组件与模块边界

- `lib/workspace-layout.ts`：常量、偏好类型、解析、序列化、静态 clamp 和容器约束计算，保持纯函数。
- `app/workspace/use-workspace-layout.ts`：浏览器宽度、Pointer Events 生命周期、localStorage 读写和 React 状态协调。
- `app/workspace/workspace-separator.tsx`：可访问分隔条、键盘调整、双击复位和恢复入口。
- `app/page.tsx`：只接入布局 hook、设置工作区 class/CSS variables，并把分隔条放到三个现有面板之间。
- `app/globals.css`：五轨桌面网格、折叠轨道、滚动容器、分隔条状态与响应式降级。
- `lib/localization.ts`：新增折叠、展开、调整和复位文案。

不把 reference 或 synthesis 的业务状态迁入布局模块，也不借 Round 12 全面拆分 `app/page.tsx`。

## 视觉与滚动

- 大于 1280px 时工作区使用 `height: 100dvh` 和 `overflow: hidden`，避免 body 再产生第四条外层滚动。
- 左侧、中心和右侧分别只在内容确实超出时内部滚动。
- 去掉左右面板原本贯穿全高的硬边框，由分隔条承担空间关系；静止时分隔条低对比，hover、focus-visible 和 dragging 时增强。
- 三栏使用同一工作台背景体系，保持现有来源安全、评分和标签分组的层级，不增加浮动卡片外壳。
- 滚动条保持可发现且低干扰，不使用完全隐藏滚动条的方案。
- 分隔条和折叠按钮具有稳定尺寸，hover 或动态图标不能引发布局跳动。

## 异常与降级

- localStorage 不可用或内容损坏：使用默认尺寸，所有业务功能继续可用。
- 拖动中窗口缩小：立即 clamp；进入 `<=1280px` 时终止拖动并使用响应式布局。
- 右侧没有选中 reference：详情轨道仍可调整或折叠，空状态保持居中可读。
- 切换语言、参考/综合稿视图或编辑状态：不得重置布局偏好。
- 浏览器不支持 Pointer Events 的目标环境不在当前支持范围；键盘调整仍作为非指针路径。

## 验收标准

- 桌面参考视图的左右栏可通过指针和键盘调整，且中间工作区不会被压到安全宽度以下。
- 左右栏可独立折叠、恢复和双击复位，业务状态不丢失。
- 宽度和折叠偏好在刷新后保持；损坏偏好会安全回退。
- 综合稿视图复用左栏宽度但不出现无意义的右栏轨道。
- 大桌面不再出现 body 与三个面板叠加的外层滚动条，三栏视觉关系更连续。
- 1280px、1024px 和 390px 延续非拖拽响应式布局，无页面级横向溢出。
- 中英文、键盘焦点、ARIA 数值和 reduced-motion 行为可用。
- 自动化测试、类型检查、lint、构建、本地浏览器和生产布局验证均有留痕。

## 风险与控制

- 指针事件遗留：集中在 hook 中清理 capture 和全局状态，并覆盖 cancel/失焦路径。
- 宽度算法互相影响：全部走纯函数，优先保证中间安全宽度，再限制被拖动面板。
- `app/page.tsx` 已较大：只做布局接线，不把业务状态迁入新模块。
- 多滚动容器仍可能显眼：移除 body 外层滚动并降低分隔视觉强度，不隐藏必要滚动能力。
- 折叠导致操作不可发现：始终保留稳定恢复按钮和 tooltip，不使用不可见热区。
- 生产浏览器控制偶发超时：动作拆分并在每一步读取尺寸、localStorage 和 DOM 状态，超时不直接记作产品失败。
